# 论文速读 Agent（paper-agent）

用中文提问，Agent 自己决定去 arXiv 搜论文、下载并读全文、在原文里定位数字，最后给出带出处的回答，或者把速读笔记保存成 Markdown。

- 模型：DeepSeek（OpenAI 兼容接口，原生 Function Calling）
- **不用任何 Agent 框架**：Agent 循环、工具调度、上下文控制都是手写的，约 600 行 Python（含评测脚本）
- **零第三方依赖**：只用 Python 标准库 + 系统的 `pdftotext`
- 带一套自动评测：10 道题，统计成功率、工具调用次数、token 和耗时

## 工作流程

```
用户问题
   │
   ▼
┌─────────────── Agent 循环（最多 12 轮）───────────────┐
│ 1. 把对话历史 + 4 个工具的说明发给 DeepSeek             │
│ 2. 模型回复：                                            │
│      ├─ 要调工具 → 执行工具 → 结果追加进对话 → 回到 1   │
│      └─ 直接回答 → 结束                                  │
│ 3. 轮数用完 → 收回工具，要求模型用已有信息收尾           │
└──────────────────────────────────────────────────────────┘
   │
   ▼
最终回答 + 逐步记录（runs/*.jsonl）
```

4 个工具：

| 工具 | 作用 |
|---|---|
| `search_arxiv` | 调 arXiv API 按关键词搜论文，返回编号、标题、作者、摘要 |
| `read_paper` | 下载 PDF 转成文字，**分段**返回（offset / next_offset），避免一次塞满上下文 |
| `find_in_paper` | 在全文里查关键词，返回附近原文和位置，用来精确定位实验数字 |
| `save_note` | 把笔记保存到 `notes/`，只取文件名，防止写到目录外 |

## 快速开始

需要 Python 3.10+ 和 `pdftotext`（macOS：`brew install poppler`）。

1. 复制配置文件，填入你自己的 DeepSeek API Key：

   ```bash
   cp .env.example .env
   ```

   然后编辑 `.env`，把 `DEEPSEEK_API_KEY=` 后面换成你的 Key。`.env` 已在 `.gitignore` 里，不会被提交。

2. 提问：

   ```bash
   python3 -m paper_agent "论文 2308.04079 在 Mip-NeRF360 上的 PSNR 是多少？"
   python3 -m paper_agent "找到 3D Gaussian Splatting 原论文，写一份中文速读笔记，保存为 3dgs.md"
   ```

3. 跑评测：

   ```bash
   python3 eval/run_eval.py
   ```

4. 跑单元测试（离线，不花钱）：

   ```bash
   python3 -m unittest discover tests
   ```

## 设计要点

- **手写 Agent 循环**（`paper_agent/agent.py`）：每轮把工具结果用 `role: tool` + `tool_call_id` 回传；模型不再请求工具即视为完成。
- **出错不崩溃**：工具出错、参数不是合法 JSON、调用了不存在的工具，都会把 `{"error": ...}` 交回模型，让它自己改参数重试。
- **上下文控制**：全文分段读取；单次工具结果超过 12000 字符就截断，并提示模型缩小范围。
- **步数上限兜底**：轮数用完时不报错，而是收回工具，让模型基于已查到的信息回答，并说明没查到什么。
- **防幻觉**：系统提示要求事实必须先查原文、注明出处、查不到就直说；评测里专门放了一道“原文没有”的反例题和一道同名论文题。
- **可追溯**：每次运行写一份 JSONL 逐步记录，包含模型每轮的回复、工具参数和结果、token 用量。
- **对 arXiv 友好**：请求间隔 3 秒；PDF 和转出的文字缓存在 `cache/`，同一篇只下载一次。

## 评测

题目在 `eval/tasks.json`，分 5 类：查编号、同名论文、查原文数字、原文没有的反例、生成并保存笔记。判分是确定性的规则（回答里是否包含正确编号 / 数字，笔记文件是否存在且包含关键内容），不依赖模型打分。

### 结果（deepseek-chat，2026-10-26，每个版本各跑 1 次）

| 版本 | 通过 | 平均工具调用 | 平均轮数 | 空结果搜索 | 平均输入 token |
|---|---|---|---|---|---|
| v1 初版 | 10/10 | 2.8 | 3.1 | 2 次 | 10012 |
| v2 改进搜索 | 10/10 | 2.2 | 2.5 | 0 次 | 8546 |

**评测发现的问题**：v1 里，模型用完整标题搜 “Attention Is All You Need”“3D Gaussian Splatting for Real-Time …” 时返回空结果。原因是 arXiv 不索引 is、for 这类停用词，查询里出现一个，AND 连起来就一条都匹配不到。模型只能换关键词或者按作者名再搜，4 道查编号的题平均要搜 2.5 次。

**改进**（`tools.py` 的 `search_arxiv`）：去掉停用词；查询有 2 个词及以上时，先按标题短语 `ti:"…"` 精确搜，再合并关键词搜索的结果。

**效果**：4 道查编号的题都变成 1 次搜索就找到，这 4 题的输入 token 合计从 26950 降到 11852（-56%）。

说明：
- 两个版本都是 10/10，这套题对正确率区分度不够，需要加更难的题。
- 每个版本只跑了 1 次，模型输出有随机性，数字会有小幅波动。
- 耗时没有放进对比：v1 包含首次下载 PDF 的时间，两次不可比。

## 局限

- 只支持 arXiv 上的论文；PDF 转文字会丢掉表格结构，公式会变成乱序字符。
- 判分规则比较粗：只检查关键字符串，不判断解释是否正确。
- 大 PDF 首次下载慢（3DGS 原文约 36MB，国内网络下实测约 5 分钟）。
- 评测题只有 10 道，结果只能说明这几类任务上的表现。
