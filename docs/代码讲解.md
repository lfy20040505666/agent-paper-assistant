# 代码讲解

建议按这个顺序读：先看第 1 节的例子弄懂整体流程，再对照第 2 节逐个文件读代码，最后用第 3 节的问题自测。

## 1. 先看一个完整的例子

问题：“论文 2308.04079 在 Mip-NeRF360 上的 PSNR 是多少？”

**第 1 轮**：程序发给 DeepSeek 的内容大致是：

```json
{
  "model": "deepseek-chat",
  "messages": [
    {"role": "system", "content": "你是一个论文速读助手……（工作规则）"},
    {"role": "user", "content": "论文 2308.04079 在 Mip-NeRF360 上的 PSNR 是多少？"}
  ],
  "tools": [ {search_arxiv 的说明}, {read_paper 的说明}, {find_in_paper 的说明}, {save_note 的说明} ]
}
```

模型不会直接回答，而是回复“我要调用工具”：

```json
{"role": "assistant", "content": "",
 "tool_calls": [{"id": "call_1", "function": {"name": "find_in_paper",
                 "arguments": "{\"arxiv_id\": \"2308.04079\", \"keyword\": \"PSNR\"}"}}]}
```

注意：**模型自己不会执行任何东西**，它只是输出了一段 JSON，说明想调用哪个函数、传什么参数。真正执行的是我们的程序。

**程序执行工具**：`tools.dispatch("find_in_paper", {...})` 下载 PDF、转成文字、搜索 “PSNR”，把附近的原文片段变成 JSON 字符串。

**第 2 轮**：把模型刚才的回复和工具结果都追加进对话，再发一次：

```json
{"role": "assistant", "content": "", "tool_calls": [ ...call_1... ]},
{"role": "tool", "tool_call_id": "call_1", "content": "{\"hit_count\": 5, \"hits\": [{\"snippet\": \"…Table 1… 27.21…\"}]}"}
```

`tool_call_id` 必须和上一条里的 `id` 对上，模型才知道这是哪次调用的结果。

**第 3 轮**：模型看到 Table 1 里的数字，不再调工具，直接回答“27.21，出自 Table 1（Ours-30K）”。程序发现回复里没有 `tool_calls`，循环结束。

整个 Agent 就是不断重复：**发对话 → 模型要么调工具、要么回答 → 调工具就执行并把结果放回对话**。

## 2. 逐个文件读

### `paper_agent/llm.py`：和 DeepSeek 通信

- `chat(messages, tools)` 就是一次 HTTP POST 到 `/chat/completions`，请求体就是上面那段 JSON。
- `temperature: 0`：让输出尽量稳定，评测结果才可比。
- 重试：遇到 429（限流）和 5xx（服务端错误）时，按 1、2、4 秒等待后重试；400、401 这类是请求本身错了，重试没用，直接报错。

### `paper_agent/tools.py`：4 个工具

- **`TOOL_SCHEMAS`**（文件末尾）：给模型看的“说明书”。模型完全靠这里的 `description` 和参数说明来决定什么时候用哪个工具。写得好不好，直接影响 Agent 表现。
- **`search_arxiv` 的停用词和标题短语**：第一次评测发现，查询里带 is、for 等词时 arXiv 一条都搜不到，因为 arXiv 不索引这些词。现在会先去掉它们；多个词时还会先按标题短语 `ti:"…"` 精确搜一次。这是“评测 → 看 trace 找原因 → 改工具 → 重跑对比”的一个完整例子，README 里有改进前后的数字。
- **`dispatch(name, args)`**：按名字找到函数执行，并把所有异常都变成 `{"error": "..."}`。这样模型传错参数时，能看到错误信息自己修正，而不是让整个程序崩溃。
- **`read_paper` 为什么分段**：一篇论文转成文字有 8 万字符左右，一次全塞进对话会很贵，还会挤占上下文。所以每次只读一段，用 `next_offset` 告诉模型下一段从哪开始。
- **`find_in_paper` 为什么存在**：找某个数字时，从头读整篇太浪费。先搜关键词定位，再读附近内容，token 消耗少得多。
- **`save_note` 的安全处理**：`Path(filename).name` 只保留文件名。如果模型传了 `../../xxx`，也只会写进 `notes/` 目录，不会覆盖别的文件。
- **缓存和限速**：PDF 和转出的文字存在 `cache/`，同一篇只下载一次；两次请求 arXiv 至少间隔 3 秒，这是 arXiv 官方的要求。
- **`fetch` 参数**：下载函数可以替换。测试时换成假的，就能完全离线测试。

### `paper_agent/agent.py`：Agent 循环

- **`run()` 里的 `for … else`**：Python 里，`for` 循环没有被 `break` 打断、正常跑完时才会执行 `else`。在这里就是“轮数用完了，模型还在调工具”的情况。这时不给工具，追加一句“请直接回答”，强制模型收尾。
- **`_ask()`**：只把 `role`、`content`、`tool_calls` 放回对话历史。推理模型（deepseek-reasoner）会额外返回 `reasoning_content`，官方要求不能回传，这里顺便过滤掉了。
- **`_run_tool()`**：模型给的参数是 JSON **字符串**，要先 `json.loads`。解析失败就把错误交回模型，不执行工具。工具结果超过 12000 字符就截断，并提示模型缩小范围。
- **trace**：每一步写一行 JSON 到 `runs/*.jsonl`。Agent 答错时，打开这个文件就能看到它在哪一步走偏了。

### `eval/run_eval.py`：评测

- 每道题的判分规则写在 `tasks.json` 的 `check` 里：回答必须包含哪些字符串、匹配什么正则、笔记文件是否存在。
- 判分**不用大模型打分**，全是确定性规则，结果可复现；缺点是只能检查关键字符串，判断不了解释是否正确。
- 题目刻意包含两类“陷阱”：
  - `ambiguous_gaussianeditor`：有两篇同名论文，看 Agent 会不会只给一篇。
  - `negative_scannet`：原文根本没有 ScanNet 实验，看 Agent 会不会编造结果。

### `tests/`：离线单元测试

- `ScriptedLLM` 是假模型，按预先写好的剧本回复，用来测试循环逻辑：工具调用、坏参数、轮数上限、截断、trace。
- `FakeFetch` 是假网络，用来测试 arXiv 结果解析和缓存。
- 跑测试不联网、不花钱：`python3 -m unittest discover tests`

## 3. 面试常见问题（先自己答，再看参考）

**Q1：Function Calling 是怎么工作的？模型真的执行了函数吗？**
没有。模型只输出“想调哪个函数、参数是什么”的 JSON，由我们的程序执行，再把结果作为 `role: tool` 的消息放回对话。

**Q2：为什么不用 LangChain？**
这个项目的目的是弄懂 Agent 的原理。循环本身只有几十行，自己写可以完全控制重试、截断、日志；需要多 Agent 协作或复杂编排时，再考虑 LangGraph 这类框架。

**Q3：怎么防止 Agent 死循环？**
设了最大轮数。轮数用完时不直接报错，而是收回工具，让模型基于已有信息回答，并说明哪些没查到。

**Q4：上下文太长怎么办？**
三层处理：论文分段读；提供关键词定位工具，避免整篇读；单次工具结果设上限，超了就截断并提示模型。还可以进一步做的：把早期的工具结果压缩成摘要。

**Q5：怎么减少幻觉？**
系统提示要求先查原文、注明出处、查不到就直说；评测里专门放了“原文没有”的反例题来检验。

**Q6：怎么评估一个 Agent？**
固定一组题，用确定性规则判分，统计成功率、平均工具调用次数、token 和耗时；每次改提示词或工具后重跑，对比前后变化。

**Q6.5：举一个你通过评测改进 Agent 的例子。**
看 trace 发现查编号的题平均要搜 2.5 次，其中有空结果。原因是 arXiv 不索引停用词，AND 查询会落空。于是给工具加了停用词过滤和标题短语搜索，重跑后这类题都是 1 次搜索命中，输入 token 降了 56%。这个改进是改工具，不是改提示词：与其让模型学会绕开问题，不如让工具本身更好用。

**Q7：工具出错了怎么办？**
所有异常都转成 `{"error": ...}` 交回模型，由模型决定换参数重试，还是换一个工具。

**Q8：如果要上线给很多人用，还缺什么？**
- 并发和异步请求
- 用户隔离和鉴权
- 费用上限
- 更完善的提示词注入防护：论文内容也可能包含恶意指令
- 监控面板
